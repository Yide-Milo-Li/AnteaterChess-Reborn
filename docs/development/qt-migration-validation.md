# Qt migration validation

Baseline: 8fc6f7d. Local validation date: 2026-10-04. This record distinguishes
implementation, automated verification, rendered inspection and external release
acceptance. Candidates remain local; no remote CI or release publication is claimed.

## Preserved behavior and baseline

The original GTK manual, handlers and integration checks provide the interaction
reference: left selects, right submits; typed coordinates accept lowercase/outer
whitespace; F11 toggles and Escape restores; cancellation does not apply promotion;
back/navigation cancels jobs; end/new/quit require confirmation. Rules, Session and
Tournament/repetition/undo tests are retained. Experimental is the approved deletion.

Before extraction, tools/dev/ai_reference.c captured 27 positions in the immutable
tests/fixtures/ai-evaluation-baseline.txt: a constant-clock depth-2 search, full
score, SEE aggregate, legal moves, completed depth, selected move and node counts.
It contains a fixed-seed legal sequence plus chain, promotion and en-passant boards.
Expected data is never regenerated by the comparator.

Isolated baseline Windows smoke tests with and without the Cairo internal scan
both exited 0 on Cairo 1.18.6-2. The historical failure was not reproduced; the
source comment is not accepted as a root-cause diagnosis. GTK is retained through
Git history and baseline build artifacts during the cutover.

## Host evidence

Windows 11 x64: MSYS2 UCRT64 Qt 6.11.2; Ubuntu 24.04 x64 under WSL2/WSLg: Qt 6.4.2.
Both Release trees passed all 21 CTest targets (18 core/C++/AI-reference, one runtime,
one desktop Qt Test and one Quick Test). Logs are under build/qt-migration/.

Desktop tests cover all modes, copied board/history, log diagnostics, completed
AI/hints, moves during hints, undo, timeout, replacement, navigation and close during
search. They cover promotion/cancel, coordinates, left/right event mapping, keyboard
focus through ticks, F11/Escape and confirmation accept/reject. Resource checks cover
all 14 pieces and four icons at 32/96/160 pixels.

Rendered inspection includes Windows and WSLg main menu, modes, setup and gameplay.
The board/side panel are kept separate and the existing dark palette/SVGs retained.
Further DPI/software, packaging and sanitizer evidence is recorded below when run.

## Acceptance limits

WSLg is an actual Ubuntu desktop surface on the Windows host, not a separately
provisioned Ubuntu workstation. Clean-PATH runtime verification isolates developer
DLL/QML paths on this host; it is not a fresh Windows installation. Remote CI and
independent human display/interaction acceptance remain distinct requirements.
The migration cannot be marked fully release-accepted until these external checks
are completed. Original PDFs/COPYRIGHT and original regression fixtures are retained.

## Rendering and portable cutover checks

Windows and WSLg/X11 passed rendered-page checks at forced scale factors 1, 1.5
and 2, plus software rendering. Menus, gameplay, fullscreen, promotion and
confirmation screenshots were inspected; confirmation buttons were adjusted to
retain dark-theme contrast. Native render runs are serialized to avoid focus
competition between Windows and WSLg windows.

Both host candidate runtimes passed --version and --smoke-test outside the source
cwd. Windows passed with Qt/QML environment paths removed and PATH restricted to
the extracted runtime/System32. Qt deployment required an explicit relocatable
qt.conf; the isolated probe exposed this before GTK retirement. Windows checks
record 24 dependency packages and a full inventory with licenses; indirect GLib
is present through Qt's HarfBuzz/font dependency chain, while GTK/Cairo/GdkPixbuf
files and loaded modules are rejected. Linux records system package/ldd details.
The old application/platform sources, GResource manifest and Make graph are removed;
the fixed Git baseline remains the rollback reference.
